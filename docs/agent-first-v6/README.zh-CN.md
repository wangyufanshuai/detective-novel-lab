# 第六轮：街坊约定与真实履约

2026-11-02。继续 Agent 内核优先、轻量 2D 界面的路线。在既有目标安排中加入有出处的社交约定，没有启用真实模型调用。

## 现在的行为

两名居民真正完成一次普通交谈后，目标模式下的一方可以提出下次在咖啡馆见面。另一方会按自己的需求、已有约定、信任和道路可达性接受或拒绝。提出与回复分别留下事件，关联到刚完成的交谈。

接受后，居民在约定前预留赴约时间，沿现有道路前往咖啡馆。双方实际到场且都能继续时，才开始一刻钟的约定交谈。只有共同交谈完整结束才算履约，并沿用已有的记忆、每日目标与社交结果规则。

- 当前样板约定为每日 13:00 的咖啡馆见面，提前 45 分钟开始安排前往；最晚 13:15 开始，13:30 前完成。
- 每名发起者每天至多提出一次，同时只保留一项未结束承诺。拒绝也占用当日发起机会；整个三日窗口保留有界记录，不丢弃活动中的承诺。
- 吃饭、睡觉、精力不足、已有持续行动和当面询问优先。已有行动会按其实际进度完成或中断，居民不会瞬移赴约。
- 对方没有到场，约定会过期；交谈被询问等因素打断，则取消履约。失败不自动生成指控、案件证据或信任惩罚。
- 即使后台知道某人已无法行动，另一人也不会提前获知原因而放弃赴约。到场者只能得知约定没有如期开始；缺席者不会凭空获得咖啡馆的现场记忆。
- 切回“按日程生活”只停止生成新的约定，已经接受的承诺继续保留。旧存档的读取不会自动新增约定。

这是明确编写的确定性邀请与回复规则，不是开放式对话协商或 LLM 的自主推理。时间和地点当前固定，后续才扩展到可协商时段、送物、调查约见等任务。

## 如何查看

打开 `/town-play/agent-first` → 街坊 → 启用三日生活 → 按目标安排。到访咖啡馆并让时间继续，就可能亲眼看到“等候街坊赴约”或“赴约交谈”。只有当前同地点可见活动会显示；未来约定、拒绝理由与内部承诺表不会公开给玩家。

实际浏览器检查在自然创建的新手记中，于第 1 日 13:05 观察到宋棠正在赴约交谈。测试只使用正常访客的启用、到访与等待命令，没有注入存档、读取隐藏约定或挪动居民。截图保留在 `output/playwright/resident-appointments-v6-*.png`。

## 规则与可追溯性

约定记录区分 proposed、accepted、declined、running、completed、missed、cancelled。所有阶段保留真实来源事件；接受不能替代履约，开始也不能替代完成。

执行边界核对所属世界、参与者、时间窗口、地点和来源。联合行动完成时再次核对实际行动、参与者、地点、持续时间及开始事件。重复提议、重复终结、伪造来源或跨世界记录不会产生第二次履约。

沿用既有世界时钟、道路、存档、检查点和事务接口，没有另建一套平行模拟器。日程模式默认不生成约定；目标模式开启后才会从真实交谈产生邀请。本轮也补上未启用生活时的提前返回，避免给旧引擎额外构造生活事件索引。

自然运行的各类约定数量见 [outcomes.zh-CN.md](./outcomes.zh-CN.md)，受控异常情境与自然运行分开记录。

- 目标模式五个种子各运行 72 小时；每个都检查需求、材料、记忆和约定来源、中途恢复与独立重放。另有一个日程种子的三日回归，不能声称本轮重新验证了五组日程对照。
- 既有目标、认知、生活边界、工作、玩家接口、实际 API／SQLite 与提供者故障恢复分别回归。
