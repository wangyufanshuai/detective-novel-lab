# Scenario Pack And Review Bundle

This note defines the packaging boundary for Review Mode. ScenarioPack v1 is now implemented as portable JSON with export, validation, and import preview APIs. The current version still keeps the SQLite schema unchanged and stores run/replay history in runtime JSON.

## Goals

- Make scenario experiments portable across machines and CI runs.
- Keep reviewer output stable enough for PR review, external agents, and benchmark comparisons.
- Avoid another large runtime migration while `PersistentTownRuntime` is still evolving.
- Preserve the existing public exports and API response envelope.

## Borrowed Patterns

From GOD-style experiment packaging:

- Treat an experiment as a directory or archive with a manifest, runnable config, metadata, and optional docs/assets.
- Keep the manifest small and machine-readable.
- Make outputs reproducible by recording seeds, runtime mode, pass criteria, and artifact hashes.

From cultivation-world-simulator-style long-world simulation:

- Keep the simulation loop phase-oriented instead of growing one monolithic tick function.
- Let each phase expose its input and output contract, even when the implementation still runs in one local TypeScript process.
- Prefer replayable snapshots and diffs over opaque "latest state" debugging.

## ScenarioPack

`ScenarioPack` is the import/export unit for scenario experiments. It is not persisted as a new SQLite table in this version; built-in packs are generated from the current world, and imported custom packs are stored in runtime JSON.

```json
{
  "manifest": {
    "id": "pack-town-review-001",
    "name": "Town Review Baselines",
    "version": "1.0.0",
    "schemaVersion": "scenario-pack.v1",
    "author": "Detective Novel Lab",
    "description": "Portable detective town scenario pack.",
    "createdAt": "2026-06-29T00:00:00.000Z",
    "entrypoint": "scenario.json"
  },
  "world": {
    "seed": "pack-baseline-hard-logic",
    "mode": "showcase",
    "timelineHours": 24,
    "locations": [],
    "npcs": [],
    "institutions": [],
    "professions": []
  },
  "rules": {
    "enabledModules": ["institutions", "professions", "long-actions", "public-opinion", "evidence-contamination", "case-aftermath"],
    "phaseConfig": { "snapshotEveryTicks": 1, "maxRunningLongActions": 8 },
    "thresholds": {
      "maxEvidenceContamination": 70,
      "maxPublicOpinionHeat": 80,
      "minInstitutionTrust": 35
    },
    "longActionKinds": ["investigate-scene", "file-police-report", "publish-rumor"]
  },
  "scenario": {
    "id": "baseline-hard-logic",
    "name": "Baseline hard-logic pass",
    "seed": "pack-baseline-hard-logic",
    "baselineSteps": 45,
    "branches": [],
    "passCriteria": {
      "minValidCandidates": 1,
      "requireHardLogic": true
    }
  },
  "expectations": {
    "minValidCandidates": 1,
    "minEvidenceCoverage": 80,
    "maxEvidenceContamination": 70,
    "maxPublicOpinionHeat": 80,
    "benchmarkPreset": "quick-10"
  },
  "docs": { "README.md": "# Baseline hard-logic pass\n" },
  "assets": {}
}
```

Required fields:

- `manifest.id`, `manifest.name`, `manifest.version`, `manifest.schemaVersion`, `manifest.entrypoint`.
- `world.seed`, `world.locations`, `world.npcs`, `world.institutions`, `world.professions`.
- `rules.enabledModules`, `rules.thresholds`, and `rules.longActionKinds`.
- `scenario` as a `ScenarioConfig`.
- `expectations`.

Safety checks:

- exported packs strip runtime snapshots and benchmark latest artifacts.
- validation rejects absolute local paths, API-key-looking values, runtime snapshots, and hidden debug logs.
- import supports preview-only validation before mutating runtime JSON.

Implemented local companion:

- replay dataset index at `data/replay-store/index.json`, generated by `npm run replay:audit`.

Deferred fields:

- signed artifact hashes.
- WorldPack references.
- zip archive wrapping for multi-file assets.

## ReviewBundle

`ReviewBundle` is the current export artifact. It is available now through:

```text
GET /api/v1/query/town/review/export?worldId=...&scenarioId=...&from=...&to=...&format=json|markdown&includeBenchmark=true|false
```

Required contents:

- run summary and full `ScenarioRun`.
- `ScenarioReport`.
- selected `from` and `to` snapshots.
- selected `TownStateDiff`.
- selected branch comparison.
- optional latest benchmark report.

The bundle must not contain API keys, local environment values, or hidden culprit details that the current exported surface has not already unlocked through the scenario/report API.

## WorldPack

`WorldPack` is a later package for full reproducible world replay. It should include:

- world manifest and seed.
- source world options.
- optional imported novel/world graph provenance.
- ScenarioPack references.
- replay dataset index references.
- expected benchmark envelopes.

This is intentionally out of scope for the current Review Mode cleanup.

## Run Catalog

Run Catalog v1 derives comparable replay data from runtime JSON:

- `RunCatalogEntry` for live and scenario runs.
- `RunSnapshot` from public Time Machine snapshots, including rule summaries.
- `RunDiff` from adjacent snapshots, including institution/public-opinion/evidence changes.
- `RunCommand` from scenario interventions.
- `RunComparison` for two run ids.
- `RunReplayBundle` with manifest, snapshots, diffs, commands, and optional benchmark summary.

The API is intentionally replay-store shaped. v2.6 adds a local SQLite replay catalog as a rebuildable query index while keeping replay-store files as the artifact source of truth.

Replay-store artifacts also have a local file catalog: `data/replay-store/index.json`. That index is generated from artifact manifests, file hashes, graph checks, and safety checks. `npm run replay:sync` mirrors the metadata into SQLite for Review Mode filtering and inspection without storing artifact body text, hidden truth, checkpoints, API keys, or absolute paths.

## Phase Boundary

The current `persistent-town.ts` remains the facade. Internally, the tick pipeline is organized around these phases:

```text
observe -> update-goals -> score-actions -> execute-actions -> observe-events -> propagate-memory -> apply-consequences -> advance-case-chain -> trigger-case -> extract-candidates -> finalize
```

Current implementation notes:

- `score-actions` selects tick actors and creates action plans.
- `execute-actions` consumes action plans and creates events, observations, memories, consequences, and decision traces.
- relationship and location evolution are applied through a dedicated action-evolution helper.
- `extract-candidates` includes generation plus local validation.
- `finalize` writes the tick report and Time Machine snapshot.

Future extraction should move phase helpers into domain services only after tests pin the existing public behavior.
