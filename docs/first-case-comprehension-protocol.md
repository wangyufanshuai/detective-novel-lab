# 首案理解度研究协议

协议标识：`first-case-observer-20260906-v1`。当前状态：**材料与工具准备；尚无真人数据**。

本轮是在同一台本机上依次进行的 5 人形成性可用性研究。对象为首次接触本案、没有看过答案的玩家，范围仅为「午夜合唱 / 公开追责」首案「印刷低语」。目前没有参与者，不发布、不招募、不联系第三方。自动化检查和主持预演均不得计为真人表现。

5 人适合寻找可复现的理解障碍；本轮不估计总体通过率，不作显著性检验，不声称代表所有玩家。GOV.UK 建议可用性研究每轮通常使用 4–8 人，而量化比较需要更大样本；这里采用小样本形成性研究的用途。[研究轮次与人数方法](https://www.gov.uk/service-manual/user-research/plan-user-research-for-your-service)

## 参与条件与材料分离

正式记录使用 `P01` 至 `P05`，按到场顺序分配，不能按表现挑选五个最佳结果。参与者应为可独立同意参与的成年人，未参与项目设计、实现或调试，未玩过本案，未看过攻略、答案或本次主持评分材料。可以有其他推理游戏经验；在外部表记录「无 / 偶尔 / 经常」，不据此组成虚假的对照组。

P 编号表示本轮样本位置，发生中断替补后可能对应不同的人。每位实际参与者的记录以本轮档案名称、P 编号和控制台自动生成的 attemptId 联合定位。主持在观察表登记这三项，结束时将同样信息交给参与者作为后续联系凭据；例如轮次 `first-case-round-01`、位置 `P01`、尝试 `A000001`。新轮使用不同档案名称；不得仅凭 P 编号判断不同轮次或不同尝试属于同一人。

自动化与熟悉项目的人员仅能预演，使用 `mode=rehearsal`、`participantId=R01`、`humanAttested=false`。正式开始前主持人核对实际真人、自愿同意、首次接触和版本一致，再设置 `humanAttested=true`。该勾选是主持声明，工具不能证明参与者身份或未看答案。

## 流程与中性口径

建议安排 5 分钟说明与设置、最多 30 分钟游戏、5–10 分钟回顾；两人之间预留 15 分钟重置和整理。正式参与者不做同案练习。主办人员先用 R01 做一遍工具预演，只验证记录流程，不推断陌生玩家理解度。

固定任务原文：

> 请把自己当作第一次来到这里的玩家，按自己的理解调查当前案件，尝试让游戏认可你的结案判断。操作时可以说说你在想什么；不确定、不同意或想停下来都可以直接说。我们想了解界面和流程哪里清楚、哪里让人困惑。

开场不列出按钮名、行动顺序、证据分组含义、嫌疑人、动机、手法或必需证据数，不示范一次正确操作。固定任务说完、案件起点已可操作时，主持人点击开始，并说「现在可以开始」。计时不包含主持人启动世界的时间，因此首次行动耗时不能被解释为完整首页入口体验。

主持主要观察；游戏过程中不纠正玩家推断，不用「对」「就是这样」确认其结论，不在参与者未发现某区时提示去看。主持人可以响应求助，但先记录帮助等级，之后的完成不再满足严格独立完成。中性任务与少干预遵循官方主持研究建议。[主持可用性研究](https://www.gov.uk/service-manual/user-research/using-moderated-usability-testing)、[避免操作暗示](https://userresearch.blog.gov.uk/2019/08/05/advice-for-better-moderated-usability-testing/)

不安排强制错误提交。若自然发生拒绝，观察其反馈理解和恢复；若没有发生，拒绝反馈题记「未遇到」，不能为补齐数据破坏独立阶段。游戏结束后再做两组证据理解问答，不回流修改本轮成绩。

## 打点与字段合同

独立主持控制台使用 `performance.now()` 计算相对秒数，主持人根据可见行为手动打点。它不读取玩家窗口、服务器隐藏答案或自动判定行动。这是观察记录工具，包含反应延迟和误点误差，不是精确行为遥测。

| 字段 | 定义与记录规则 |
| --- | --- |
| `schema` / `protocol` | `detective.first-case-observer.v1` / `first-case-observer-20260906-v1` |
| 集合 `lastAttemptNumber` | 已分配尝试号的非个人计数；新导出携带，旧导出缺此字段时从已有最大尝试号迁移。撤回或清空不回退；恢复取本机与备份的较大值，避免本机重新分配已使用的尝试号 |
| `mode` | `human` 或 `rehearsal`，两者分开分析 |
| `participantId` / `attemptId` | 正式样本位置 P01–P05，预演 R01；尝试号自动生成，如 A000001；新参与者替补时分配新尝试号，原中断尝试保留 |
| `buildId` / `caseLabel` | 冻结构建标识 / 印刷低语，不是答案或隐藏 case ID |
| `humanAttested` | 主持对真实、符合条件、自愿参与的声明；预演必须为 false |
| `status` | `active`、`completed`、`abandoned`、`interrupted`；completed 表示主持已确认理论接受及最终解答复核完成（7/7），两项确认不另存字段 |
| `elapsedSeconds` | 从固定起点到游戏停止的整数秒，不含回顾访谈 |
| `firstEffectiveActionSeconds` | 首次可见成功调查操作的相对时间；未观察到或漏记为 null，不能写 0 或用猜测补齐 |
| `currentStage` | join / observe / search / question / challenge / organize / submit / review |
| `events` | 有界相对事件记录，最多保留最近 200 条；不是全部点击历史，不存对话或答案正文 |
| `helpCounts` | neutral / directional / direct / takeover 四项非负计数；按一次连续帮助干预计一次 |
| `confusions` | objective / control / evidence / claim / rejection / other 的去重集合；不是错误次数 |
| `motiveRating` / `methodRating` | correct / partial / incorrect / not-assessed；根据结束后解释评分 |

首次有效行动必须是当前案件中可见已成功的实际调查操作，例如成功加入调查、成功观察 / 搜查 / 询问 / 质证，或已加入后实际改变调查证据选择的操作。单纯移动鼠标、滚动、关闭说明、切换布局、调整感官设置、只把字填入未提交文本框不算。失败、阻断、取消、被拒绝或无法确认结果的操作不算。通常第一个有效行动是加入调查；不能把自动化接口成功等同于主持已观察到。

只在首次有效行动发生后立即打点一次。漏点时保留 null，并在外部表记录漏点原因；不要事后制造秒数。外部表同时记录计时方式、窗口尺寸、系统切换导致的观察盲区和已知误点。若额外使用人工秒表或录像校验，必须标明来源，不能把观察时间写成系统埋点。

阶段是观察位置，不是要求玩家遵循的路线：organize 包括选择嫌疑人、选入证据、两组论证和可选笔记；submit 包括被拒绝后的修订；review 为公开接受结果出现后，玩家进行最终解答复核的阶段，此时仍计游戏时间。允许回到先前阶段。放弃时以最后实际阶段为准，不按主持人希望进行到哪一步填。

## 帮助分级与完成定义

| 等级 | 例子 | 是否仍是严格独立完成 |
| --- | --- | --- |
| 无干预 | 固定开场、安静观察；参与者自行阅读界面已有固定提示 | 可以 |
| neutral | 游戏过程中额外说「你现在在想什么？」或重述任务；不指方向 | 不可以 |
| directional | 指向一个区域或提示查看某一控件 | 不可以 |
| direct | 给出具体操作步骤、解释证据分类含义、举本案解题例子 | 不可以 |
| takeover | 主持代点、代填、代选、使用调试操作替参与者推进 | 不可以 |

固定开场、计时开始提示、统一结束通知和停止后的访谈不计入帮助。所有游戏中的额外促进行为均记录，即使中性、不涉及答案，也按照本轮较严格口径排除「独立完成」。界面自带固定提示是被测产品的一部分；若有人使用产品自动完成或答案填充能力，在外部表另记，不能称为理解证据。不得向参与者解释评分会因求助下降，以免阻碍真实求助。

`completed` 需要主持同时观察到本案公开理论接受和玩家完成最终解答复核（首案 7/7），再勾选控制台两项确认。只接受理论而未复核、点击提交、按钮可点或主持觉得答案正确都不算。**严格独立完成 = completed 且四类 helpCounts 全为 0**。两组理解评分独立报告，不能因通关而自动记 correct，也不能因结案失败就自动记 incorrect。

## 停止、排除和替补

1. 已公开接受理论且玩家完成最终解答复核（7/7）：停止游戏计时，记 completed，再访谈。只接受但尚未复核时继续记录 review 阶段。
2. 参与者决定不继续，或到 30 分钟仍未完成这两项：停止游戏计时，记 abandoned，保留在分母。愿意继续的探索可在访谈后另作预演观察，不延长正式时长。
3. 游戏自身报错、状态无法推进、关键控件不可用：作为产品问题保留，最终不能继续则记 abandoned；不可用 interrupted 洗掉产品失败。
4. 场外电话、临时离开、设备断电、研究设施故障使条件不再可比：记 interrupted，外部表说明可核实原因，保留原 attemptId。同 P 编号由另一位未接触答案的新参与者替补。已玩过的同一人不能重新当陌生玩家。
5. 计时前已发现看过答案、不满足参与条件或版本错误：不开始正式记录。计时后发现招募条件错误或答案外泄，记 interrupted 与具体原因，不静默删除；后续更换参与者。
6. 仅拒答访谈：保留 completed / abandoned，其评分为 not-assessed，不替补。漏打点也不构成替补理由。
7. 参与者撤回数据同意：立即停止，按本轮档案名称、P 编号和 attemptId 核对并移除其可关联研究记录，停止分析该数据。不能连带删除沿用同 P 编号的其他参与者。处理导出、笔记及副本后重新分析；仅保留不关联个人的撤回及实际缺额流程说明。撤回的若只是早先的中断尝试，仍有效的替补成绩保留，不再为该位置重复招募；撤回有效尝试才由新参与者补空缺。不得伪装成产品弃玩。

同一 P 编号不能有两个 completed / abandoned 再择优；控制台分析器应报数据冲突，主持先对照原始外部表纠错。若五人未齐，状态保持数据不足；不能用预演、AI、开发人员或额外较好尝试凑足五人。

## 两组理解评分与错误归因

回顾先问开放问题，不解释标准答案。只在参与者已接触相应表单时询问对应两组；未到达且没有解释材料时记 not-assessed。主持不读取隐藏真相、不从私有证据 ID 推定其心理理解，使用参与者自己已看到的公开线索与解释。

| 评分 | 动机组 motive | 手法组 method |
| --- | --- | --- |
| correct | 用自己的话说清「为何做」的原因，并把一个已看到的线索与该原因建立合理联系 | 说清「如何做到」的实施过程，并把一个已看到的线索与实施方式 / 工具 / 痕迹建立合理联系 |
| partial | 只说对组的用途但不能解释自己选入的证据，或说明含糊、部分混淆 | 同左，针对手法组 |
| incorrect | 把用途解释错、把两组含义颠倒、仅凭名称猜测且无法说明、明确表示不知道 | 同左，针对手法组 |
| not-assessed | 未到达表单、未问、拒答、记录不足；不能当作答错 | 同左 |

这是类别用途和公开证据论证理解评分，不是对隐藏答案的第二套判定器。公开线索支持其解释的情况下，案件结论与权威判定不同也不必然说明类别理解错误。反过来，碰巧通过但解释不清不能得 correct。若解释没有可判断的公开依据，保留 partial 或 not-assessed，并写明不确定原因。

完成流程包含最终解答复核，结束访谈可能受到刚看到的解答影响。外部表注明评分依据来自「复核前自发说明 / 复核后回顾 / 两者」。本轮两组评分反映流程后的用途理解，不能据此声称玩家在揭示解答前已经独立理解。只复述解答、无法说明自己如何归组时不自动得 correct；游戏中也不为消除该限制而插入额外教导或给分提示。

每个困惑至少写一条观察依据：「发生了什么 / 玩家怎样解释 / 还有何种可能」。不能仅根据一次停顿推断其不理解。固定归因：objective=当前目标；control=控件发现或操作；evidence=已发现、已选入、证据含义；claim=两组论证用途；rejection=拒绝反馈和恢复；other=其他或尚不确定。界面技术错误先记事实，不归咎玩家。一个持续情境可有多个类别，但控制台每类只保留有无；分析报告的是涉及人数。更细的次数、严重度和因果假设只能来自注明来源的外部观察表。

## 预定义分析与开发决策

- 只分析同一冻结版、humanAttested=true 的 human 记录。完整样本为 P01–P05 各一个 completed 或 abandoned；interrupted 单列和替补，不与分母混合。
- 首次有效行动：逐次保留实际观测秒数，报告观测数和缺失数。完整五人中有任一缺失时，完整样本中位数为 null；不能只对较快的已观测者给出无说明中位数。
- 完成：同时报告 completed 人数、严格独立完成人数、弃玩人数和弃玩阶段，全部以五个有效尝试为分母。帮助人数和四类帮助次数单列。
- 理解：动机、手法各四档人数，以及两组均 correct 的人数；not-assessed 明列。完成、类别理解和结案正确性不得合为一个模糊分数。
- 归因：各困惑类别涉及人数、可复现实例、导致的阻断和归因置信依据。优先修复可复现的卡死 / 结果错误，其次是跨参与者重复的理解问题。单人严重阻断仍可值得修复。
- 收齐五人时工具只输出 `ready-for-review`，不自动宣称 human-pass；人数不足时不出完整轮次结论。若至少两人因同类问题依赖主持或放弃，将其列为下一轮首要改进候选。这是预先约定的产品优先级规则，不是统计显著性阈值。
- 报告按「观察证据 → 对玩法的影响 → 可验证的修改建议」写最多三个主要问题；把尚无证据的解释标为假设。修复后另开冻结版本、另找未看过答案的人复验，不能把本轮对照复测说成新手首次体验。

## 保存与本轮交付边界

工具只存匿名编号、分类、计数和相对时长；不存姓名、联系方式、答案正文或隐藏游戏数据。导出与外部观察表留在本机输出目录，不放 public、GitHub、旧研究数据目录或玩家页面。实际有人的记录可能包含可识别背景，整理时只保留行为所需信息。

研究准备完成只表示：启动 / 重置、主持记录、空导出、分析器和材料可以预演。真人数量仍为 0；访谈结论、独立通关率和理解度仍未测量。结果状态见 [本轮结果占位](first-case-comprehension-results.md)。
