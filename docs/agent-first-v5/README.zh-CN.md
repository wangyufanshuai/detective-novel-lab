# 第五轮：近期经历、每日目标和可切换的生活安排

2026-11-02。继续 Agent 内核优先、轻量 2D 界面的路线。新增确定性的本地目标规划，不启用真实模型调用。

## 玩家现在能做什么

进入 `/town-play/agent-first`，打开“街坊”并启用三日生活后，可以选择：

- **按日程生活**：沿用原有规则首选，作为对照和回退策略。
- **按目标安排**：居民在非紧急的单人活动中，参考自己的近期经历、需求和每日目标，选择做事或歇脚。

切换会保存安排方式，不推进世界时间，也不会重置已有行动、需求、目标进度或模型预算。旧手记读取时不自动切换。两种方式都不调用付费模型；个体记忆、目标和进度没有被加入公开玩家观察。

## 内核变化

### 近期记忆必须能核对到事件

检索现在使用原始事件的日、时、地点、参与者和完成标记。它拒绝孤立引用、未来事件、无效时间、跨世界记录和另一名居民的经历。同一天也能区分新近程度；当前地点有相关性加分，最多向提案提供六条记录。

结果继续使用人物自己的主观记忆摘要。不会把隐藏事件的完整描述、其他参与者的私有记录或案件真相补进记忆。当前实现仅检索自己参与且有事件支撑的记录；非参与者听来的流言、转述和间接观察留待后续单独建模。

这仍是明确编写的排序与行为规则，没有向量检索或语义理解。重复惩罚依据真实完成事件的活动类别和时间，不解析记忆文字中的命令。

### 每日目标有稳定进度与来源

每位居民每天拥有三个编写好的目标：推进手头事务、留出安静休息时间、与街坊交谈一次。优先级由居民身份和种子稳定确定；它们不是模型自行发明的人生目标，也不构成完整人格系统。

只有已经完成的生活行动和材料工作，才能给目标增加进度。开始、提案和中断都不算完成。每笔进度保留原始完成事件编号，同一事件不能重复记入同一目标；达到配额后目标完成。跨午夜的时长只计入当前目标日期的实际重叠部分。新的一天保留最近三日历史，未完成目标明确标为到期，不伪造完成。

当前目标的承诺编号保存在存档中，选择时给继续处理它一个小幅加分；紧急需求、道路耗时、共同交谈规则和持续行动仍然优先。

### 决策仍受现有规则裁决

目标模式只在当前已经合法的候选之间评分：需求分、未完成目标优先级、继续当前目标的小幅加分、近期重复同类完成活动的惩罚，以及确定性的微小平局处理。行动说明会跟随实际选择，避免休息却仍显示“正在履行事务”。

提案保留候选分数、选择机制、检索到的记忆和当前目标编号。目标来源与记忆来源仍会核对。模型提供者的观察版本升为 `resident-life-policy.v3`，包含本人当日目标；它仍然只能返回合法候选编号。

本地评分预算与模型请求预算分开。显式选择目标模式时，本地上限扩展至本窗口最多 `864 × 居民数` 次评分，只在有多个候选时计数；切换不会清零已用次数，也不增加模型请求预算。预算不足仍回到日程首选。

## 验证与实际对照

当前结果以本目录 `review.json`、`quality-review.json` 及各子报告为准；没有当前源码摘要的旧报告不充当本轮证据。

对照采用五个匹配种子，每种安排各运行 72 小时，检查每名居民的吃饭、睡眠、交谈、需求边界、材料守恒、来源、中途恢复和独立重放。先前已通过的首个目标种子保留在 `preflight`，其余四个在 `goals-rest`；两者必须与当前源码一致才会合并。日程组在 `rules`。

可读对照见 [quality.zh-CN.md](./quality.zh-CN.md)。目标完成率只统计完整观察的第 2、3 日；重复率根据整段实际完成事件计算；提案来源指标单独注明仅覆盖最近保留的 512 条提案。降低重复率本身不能证明更聪明，活动时长和固定规则休息也会影响它。

另有受控机制测试、真实 API／SQLite、原工作系统、原玩家接口、提供者故障恢复、限定范围 TypeScript 和实际浏览器检查。浏览器覆盖切换、等待、重载、切回与两个视口宽度；390 像素是桌面浏览器缩窄，不是真实手机验收。没有执行全仓库生产构建、百人压力测试或人工游玩验收。

## 下一步

1. 让个人目标扩展到有路线、时限和参与者的约定，并保持可中断、可履约与可追溯。
2. 在保留原始事件引用的前提下做长期记忆摘要、反思和失真流言，区分世界事实、个人信念与对外说法。
3. 用同一组任务比较少量真实模型提案的有效性、重复、拒绝率和成本，再决定哪些场景值得付费推理。

Blender 样板继续保留，本轮未开展建模。真实模型质量、完整案件推理、Windows 包、跨设备性能和人工美术认可仍未验收。
