# 第四轮：可替换的居民模型提案接口

2026-11-01。继续 Agent 内核优先、轻量 2D 界面的路线。本轮交付服务端实验路径及验证；网页访客入口仍使用规则策略。

## 做成了什么

- 生活规划器在非紧急、单人日常中提供真实选择：继续事务／短暂歇脚，或在家休息／整理个人手记。吃饭、睡觉、赶路、共同交谈和三项材料生产仍由原有规则执行。
- 模型只收到自己的有限观察、至多六条个人记忆和当前合法候选；只允许返回一个 `candidateId`，不能写人物状态、案件真相或证据。
- `commandTownLifeStep` 复用既有 SQLite 预算预留、世界版本检查、25 秒事务外等待租约和持久重试回执。预算先保存，请求在事务外进行，结果回到当前世界再裁决和推进五分钟。
- 每个三日生活窗口默认最多预留 48 次生活模型请求；同一世界／居民／时刻不能重复预留。它与旧工作提供者预算、离线评分预算分开。
- 缺配置、预算耗尽、无效 JSON、非法候选、超时和请求错误都回到当前规则首选。单次请求默认六秒、最多八秒；请求观察与响应各限 16 KiB，输出最多 96 tokens。异常信息及密钥不进入世界存档或回执。
- 相同动作的完成回执持久保存；重复请求和数据库重开不会重新调用模型。未完成请求的租约到期后，重试直接按规则恢复，迟到响应不会再次推进时间。
- 修复离线评分预算耗尽抛错的问题，预算用尽后继续按规则生活。收紧来源校验，拒绝附加伪造策略来源、伪造检索记忆和无效置信值。

## 入口与默认行为

服务端实验入口位于 `lib/world/town-exploration-store.ts` 的 `commandTownLifeStep`。它要求已启用三日生活，接收现有五分钟 `work-step` 命令和浏览器所有权凭据。

没有新增公开 HTTP 命令，也没有在 UI 中添加模型开关。真实调用同时需要服务端设置 `RESIDENT_LIFE_AI_ENABLED=1` 及现有明确的提供者配置。测试通过注入受控传输走同一生产路径；本轮没有启用真实配置、读取密钥或发送外部模型请求。

不要把预留数当作实际计费次数：崩溃可能发生在发出请求前后。公开观察新增 `modelAttemptsReserved`；没有预留时 `modelCalls=0`，一旦有预留则为 `null`，表示准确请求数未知。内部保留经过裁决的选择和提供者／模型标识，凭据不进入记录。

完成回执以浏览器会话、动作编号和包含世界／会话版本的完整命令为缓存范围。改用另一编号会重新检查当前版本；不会跨世界或跨时刻复用模型答案。候选观察包含完整策略版本、来源、需求和候选，并在入队及执行时再次核对。

## 验证与边界

执行结果见本目录 `review.json` 及各子报告，失败日志保留在 `runtime`。只在报告通过且源码摘要一致后认定对应检查通过。

- 新的提供者检查覆盖实际行动改变、存档重放、私有观察、严格 JSON、超时／流读取、错误回退、真实 SQLite、并发、重开、过期恢复和离线预算用尽后三日运行。
- 既有三日生活检查重新运行五个种子，每个 864 个五分钟步长，并覆盖中途恢复及完整重放。既有工作、生活边界、真实 API 和限定范围 TypeScript 检查另行记录。
- 浏览器检查仅覆盖公开规则路径的启用、等待、可见活动与重载，不代表真实模型的浏览器联调或设备验收。

受控响应证明接口能改变实际行为、能被规则约束且能重放；它不证明真实模型更聪明。记忆检索仍是按日级新近度、记录类型和置信值排序；本地评分只比较需求，不声称语义理解、精确事件时间或长期反思。完整案件、流言失真、人格与计划质量、百人规模和跨设备性能仍未验收。

前三轮目录保留为各自源码的历史记录；不能把它们的通过标记直接用于当前源码。Blender 样板继续保留，本轮未开展建模，也没有人工美术认可。

## 下一阶段

1. 建立生活决策质量基准：行动差异、计划坚持度、重复行为、需求满足、社交分布、来源覆盖与每个有效决策成本。
2. 加入有出处的近期记忆检索和个人目标，让模型选择有稳定的人物理由；长期摘要保留原始事件引用。
3. 再进行少量真实提供者对照，并在内部观察界面展示提案、拒绝与回退；通过后接到可选运行模式。
