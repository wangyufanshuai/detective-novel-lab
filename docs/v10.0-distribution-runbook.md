# v10.0 Distribution Runbook

This runbook turns the frozen v9.7 feature tree into a repeatable v10.0 Automation-Validated Release. It creates local evidence only. It does not push, tag, publish, release, deploy, regenerate public catalogs, or run extended 5000/10000-tick gates.

## Supported build envelope

- Node.js: `>=22 <25`
- npm: `>=10 <12`
- Windows production runtime: native `next start`
- Linux production runtime: Docker image based on Node 22 Bookworm
- AI during validation: mock provider with provider credential values cleared
- persistence during validation: unique temporary SQLite files owned by each smoke process

Install exactly from `package-lock.json`:

```powershell
npm.cmd ci --no-audit --no-fund
npx.cmd playwright install chromium
```

Then build and verify the current worktree:

```powershell
npx.cmd next typegen
npx.cmd tsc --noEmit
npm.cmd run build
npm.cmd run quality:rc -- --json
npm.cmd run qa:v10-distribution
npm.cmd run qa:v10-docker
```

## Clean worktree closure

The canonical closure is:

```powershell
npm.cmd run quality:v10-clean-worktree -- --snapshot=HEAD
```

The orchestrator creates an independent detached worktree, provisions the two byte-locked public snapshots, asserts the worktree has no `node_modules`, `.next`, untracked outputs, or `data`, runs `npm ci`, installs Chromium, runs TypeScript and a production build, performs a live production advisory audit, deletes derived state, and runs the complete `quality:rc` twice. Derived `.next`, untracked outputs, and temporary data are deleted again between the two RC runs while historical tracked samples are preserved, so the second pass cannot inherit the first pass's build or test outputs. Docker/Linux smoke is run when Docker is available.

`public/dataset-reader` and `public/review-catalog` are external byte-locked release inputs in this branch, not tracked source files. The clean-worktree orchestrator copies only those nine files and requires tree hash `a3fca1430935d4252a03db9600d792cf52eedef0984c2469b76ff45addef3c1f`. It never rebuilds, stages, or edits them. A source clone without that separately provisioned snapshot can install and build Server Runtime, but cannot claim the complete Static distribution gate.

## Distribution evidence

After a passing clean run, safe local evidence is copied to `outputs/v10-distribution/`:

- `release-manifest.json`: source Git tree, fixed product inventory, supported targets, public snapshot hash, and exclusion policy;
- `source-files.sha256`: SHA-256 for canonical Git index blobs plus the byte-locked public inputs, using relative paths only and remaining stable across checkout line-ending policy;
- `dependency-summary.json`: exact direct versions, lockfile digest, package/license counts, and integrity policy;
- `SHA256SUMS`: checksums for the evidence files;
- `clean-environment-report.json`: stage status, durations, two RC summaries, and Docker result.

These files contain no database content, credential value, absolute path, hidden truth, raw case body, internal authority record, or participant data. Verify them with:

```powershell
npm.cmd run quality:v10-evidence-safety
```

The evidence directory is ignored by Git and is not a public artifact.

## Runtime smoke and recovery

The Windows/native smoke starts a production server on a dynamic loopback port and a unique temporary database. It verifies Server HTML, Static HTML, runtime storage health, schema version 4, and both protected public JSON roots. Cleanup terminates the spawned process tree and removes the database, WAL, SHM, and journal files.

The RC invokes Static Reader QA with `--public-only`. That mode reads and scans the provisioned public snapshot directly; it neither requires `outputs/dataset-packages` nor calls the exporter. The legacy source-export mode remains available only for a separately authorized artifact workflow.

The Docker smoke builds from a context that excludes `.env`, `.env.local`, databases, outputs, Git metadata, dependencies, and build caches. The image prunes development dependencies after build, starts with mock AI and an image-local temporary database, checks Linux Server/Static health, then removes the container and smoke image.

If a gate fails, reproduce the named stage directly. Do not add fixed sleeps, reuse the default development database, refresh protected catalogs, or copy old `.next`/`outputs` into the clean worktree. Follow [v9.7-recovery-runbook.md](v9.7-recovery-runbook.md) for process and database cleanup and [v10.0-migration-policy.md](v10.0-migration-policy.md) for save recovery.
