# 侦探小镇与小说工坊：方向重置和联合开发方案

日期：2026-10-07。性质：基于当前源码、历史版本和用户本轮选择的规划；概念图不代表 Blender 成品、可玩版本或性能验收。

2026-10-08 美术方向更新：用户指出当前 Blender 外观不符合预期，并明确以“东方快车、福尔摩斯、埃勒里”为参考。后续按[古典侦探世界美术方案](../classic-detection-2026-10-08/README.zh-CN.md)制作有限范围的真实样板；以下四套图与河湾微缩外观保留为历史候选，不能视为已获艺术认可。Web＋Blender＋Agent 路线与 Windows 下载版、网页小说工作台目标不变。

## 1. 本轮已经确定的方向

用户否定了当前档案室作为“侦探小镇”的整体视觉目标，并确认：

1. 希望能像立体沙盘一样掌握人物与案件。
2. 操控界面参考《星露谷物语》。
3. 保留 Blender 3D 建模，采用角色探索和工具栏操作。
4. 旧小说项目就是 E:/xuexi/detective-novel-lab。

因此产品主画面改为：**可控制侦探行走的 3D 小镇；日常采用俯视跟随镜头，按需打开全镇俯瞰、人物日记、案件本与写作桌。**

这里采用的是探索、快捷栏和情境交互的操作思路。小镇建筑、角色、物品、图标和界面皮肤需要自行设计。四张地域/美术候选尚未被用户选定，不能把 B 自动记为艺术方向通过。

当前证据室保留为局部场景与资产技术储备。v11 的历史检查不因此失效，也不能证明新小镇的美术方向正确。v12 只有后台 Blender 草稿和三张草稿渲染，没有完成正式导出及验收；本轮不继续扩大这一房间。

## 2. 为什么之前越打磨越偏

此前主要验收单位是桌面、纸张、抽屉、材质和静态房间镜头。它们可以证明制作细节，却没有回答进入小镇后的四个问题：

- 我在哪里，接下来能走到哪里？
- 这里的人在过什么生活？
- 一宗案件如何改变这座镇？
- 我能怎样观察、交谈、查证，再把经历写成故事？

新的质量判断从“一个可辨识、有生活关系的街区”开始。近景道具只能在主镜头与调查动作已经成立后继续细化。

## 4. 已确认的操控与 UI

![Blender 3D 小镇与角色探索工具栏概念](concepts/e-exploration-interface.png)

上图是根据用户最后一次选择补绘的界面概念，采用河湾街区展示操作布局；它不代表用户已选定西式建筑。可见的角色、目标、时钟和工具栏均为概念内容，尚未接入引擎。

### 日常探索

世界是主画面。默认固定方向的斜俯视镜头，角色移动时轻柔跟随；允许有限缩放。俯视角度和角色屏幕尺寸需在小样中调校，不能直接照搬概念图中的远景构图。

- WASD/方向键移动；支持鼠标点击目的地作为备选方式。
- 靠近人物、门、可调查物件后出现一个明确交互提示；建议 E 交互，实际按键可重绑定。
- 底部初始六至八个快捷槽：放大镜、笔记本、地图、相机、证物袋、钥匙等，按案件和时代取舍。
- 右上角显示日期、时间和天气；左上角最多一条当前目标。
- 交谈时出现底部对话框；调查物件时打开局部详情；返回后保留原位置与镜头。
- M 打开地图，J 打开案件本，Tab 打开背包，Esc 返回；按钮始终提供等价鼠标操作。
- 搜索、询问、质证与提交理论使用现有认证调查动作，不能因增加快捷键绕过引擎规则。

主画面不常驻人物关系网、证据审计表和作者真相面板。也不为了相似而加入与推理无关的种田、饥饿、体力或每日强制劳动。

### 全镇俯瞰

滚轮缩小或地图按钮进入可选俯瞰模式，满足“立体沙盘掌握人物与案件”。选中地点后可定位道路和访问目标，再回到角色探索。

玩家只能看到已经公开或观察到的人物位置；离开视野后显示“上次见于某地”，而非持续泄漏所有人的真实坐标。作者模式才允许完整日程与轨迹。全镇俯瞰是相机与信息呈现模式，不直接给予传送或改写世界的权限。

### 案件本与写作桌

案件本集中承载线索、证词、人物和推断，不要求在街景中一直展示复杂连线图。写作桌为独立入口：左侧章节，中间正文，右侧按需展开人物设定、线索铺设和一致性问题。全文编辑时优先阅读与输入空间，小镇可作为可收起的场景参考。

游戏/作者身份切换必须经过服务端权限与独立投影；隐藏按钮不是防剧透边界。公开试玩从数据加载阶段就不能收到作者真相。

## 6. 联合架构：共享世界，分开知识与叙事

不新建两份平行真相库。继续利用 packages/engine，把小说模块与世界模块通过小而清晰的版本化合同连接；先不进行大规模搬目录或整体合并工作区。

共享基础是人物、地点、时间、事件、关系、来源与案件真相。上层提供三个明确视角：

| 视角 | 能访问什么 | 不能越过什么 |
| --- | --- | --- |
| 玩家调查 | 当前角色已知事实、可观察世界、已发现线索 | 不显示完整罪案轨迹、秘密或未发现证据 |
| 作者创作 | 经授权的完整设定、真相、分支和稿件版本 | 正文生成不能静默覆盖已锁定真相 |
| 读者阅读 | 当前章节之前披露的内容、可选插图 | 不能通过词条、地图或问答提前看到后续揭示 |

新增一层桥接记录，建议命名为 StoryProject/CaseStoryLink，至少记录：

- worldId、worldRevision、caseId、branchId、chapterId。
- 人物/地点在世界与稿件之间的显式 ID 映射。
- 一项事实的来源、知情角色、读者首次可知章节。
- 证据在调查中的发现条件，以及在小说中的铺设段落。
- 当前稿件依赖的真相版本、修订历史和过期状态。

这些是待设计合同，不是已有字段。已有 NovelWorldProject v2 与 NovelPersistentWorkspace v1 采用新增版本/迁移，保留旧项目与原始文本。

关键区别：

1. 世界中发生了什么，不等于某角色知道什么。
2. 某角色知道什么，不等于作者此刻要告诉读者什么。
3. 模型从小说抽取到的“文本陈述”，不自动等于已证实的世界事实；谎言、传闻和不可靠叙述要保留类型。
4. 小说需要取舍、场景、节奏、对话和主题；不能把事件日志机械扩写成章节。
5. 阅读回看、相机移动和暂停显示，不应被当作推进世界的写操作。

### 小镇到小说

选择案件和世界版本 → 锁定真相 → 安排叙述视角与线索披露 → 章节蓝图 → 分场景正文 → 一致性检查与编辑 → 形成可导出稿件。

选择事件只能读取作者授权投影。正文每次生成使用结构化真相、该章可用信息、人物声音卡、相关片段与历史摘要，不无限附加全部旧章节。

### 小说到小镇

导入原创/已获许可文本 → 抽取人物、地点和时间主张 → 核对身份与来源 → 补齐空间及行动约束 → 建立候选分支 → 检查可达性与公平性 → 生成可调查版本。

任意小说不能直接宣称“一键变成可靠游戏”。文本缺失的路程、时长、证据归属必须显式补充；补充内容保留作者输入或推断标记。

### 改稿与分支

仅改语言不改变真相版本。改变凶手、证据、时刻、位置或知情范围时，创建候选修订并列出受影响章节、路线与校验。通过约束后更新开发候选，不偷偷覆盖旧稿和已发行分支。

## 7. 小说创作恢复顺序

1. 恢复清楚的创作入口：快速模式与分步模式，项目列表、保存、续写和导出。
2. 先实现完整短篇闭环：梗概、真相骨架、时间线、线索/误导、章节蓝图、正文、修订。
3. 把输出保存为可恢复任务：逐章状态、版本、取消、失败重试、已完成章节不重复扣费生成。
4. 分开两种检查：规则检查身份/时刻/证据/披露约束；文本评阅检查节奏、人物声音、重复、情绪与中文表达。模型评阅只作候选意见。
5. 给重要事实与决定性线索建立段落级映射。结构检查不假装能完全理解自由文本；需要源段落定位与抽查。
6. 首轮完成约 8,000–15,000 字、6–8 章的短篇候选，再扩展长篇系列。字数为生产范围，质量不足不靠填充达标。

《听雪馆第十三把钥匙》优先作为导入与版本迁移样本；是否把它改成小镇首案另作内容选择，不能为适配地图随意改写原有七章。

## 8. 第一个共同样板

建议先做一个约 100–150 米尺度的街区，8–12 栋主要建筑、6 处可调查地点、12 名有明确日程的居民、1 宗完整案件。其中 3 处先提供完整室内，其余提供门口/局部调查界面。具体数量是本轮范围建议，最终以可读性和性能为准。

短循环：从侦探住处出门 → 路过居民日常活动 → 到咖啡馆问话 → 去另一地点核对时间 → 调查一件物证 → 在案件本中提出判断 → 看到结案后的生活变化。

长循环：世界继续留下可追溯事件 → 挑选具有戏剧张力的案件 → 写作桌组织同一事件的读者体验 → 形成短篇和章节插图候选。

同一现场在三个视角中不同：玩家看到已发现证据；作者看到完整因果；读者只看到当前章节披露。三者引用同一事实版本，不共享同一可见数据包。

## 9. 按既定顺序制作 3D

用户固定的五步顺序继续保留。评审对象从单间档案室扩大为完整街区与探索界面：

| 阶段 | 交付 | 放行条件 |
| --- | --- | --- |
| 0 方向与功能范围 | 操控方案、地域/美术选择、街区平面和角色尺度 | 本轮已确认 3D＋角色探索；地域风格仍待选择 |
| 1 后台 Blender 正式构图与灯光 | 主街区、地标、道路、主角与基本居民、日/暮光方案 | 主镜头能辨认主要地点、人物和可行走空间；不先投入不可见的微小道具 |
| 2 多角度渲染 | 玩家跟随视角、全镇俯瞰、四角、低机位、室内天花斜视 | 可见场景完整、建筑比例稳定、关键路径没有遮挡死角 |
| 3 Function 动线验收 | 人物尺度路径、门口/楼梯/桥梁/交互距离、初步遮挡策略 | 每个目标地点可达；人物不穿墙；切换门与室内后定位一致 |
| 4 Form 材质与比例验收 | 建筑家族、角色轮廓、材质色板、昼夜层级、HUD 可读性 | 主要屏幕尺度可读；世界、角色和 UI 统一；输出对应的 agent 评阅记录 |
| 5 浏览器和目标设备性能验收 | 实际资产加载、持续步行/切场景/多人活动、输入、保存恢复 | 源资产与浏览器版本一致；本机与实体目标设备分开记录；未测设备保持未验证 |

Function 的 Blender 几何检查只是第一层。角色行走、鼠标点击、键盘焦点、对话返回和屋顶遮挡，还要在第五阶段检查真实运行时。

### 建模与性能的工作约束

- 建筑采用可复用墙体、屋顶、门窗、栏杆和街面模块，独特地标保持单独设计；每处可交互入口有稳定 ID。
- 主镜头优先保证轮廓、色块、角色辨认与道路留白。瓦片纹路和家具内构不成为街区立项前提。
- 静态光照可烘焙，日夜变化需要独立的可验证方案；不得把现有房间静态光照成绩直接套到室外多人场景。
- 规划资产分块、实例化、纹理压缩和室内按需加载。是否使用每项优化由实际测量决定，不为“顶级”堆复杂度。
- 初始预算建议：主街区可见三角形 300k–500k、主视图绘制批次不高于约 150、首个可玩街区压缩传输约 20 MB 内。均为待测预算，不是已达标结果。
- 桌面目标为稳定接近 60 fps，p95 帧间隔不超过 20 ms；低配档目标 30 fps，p95 不超过 36 ms。必须注明真实设备、分辨率、渲染比例、质量档和刷新率。
- 性能至少覆盖十分钟移动/切换/交互循环；首屏加载另外记录冷缓存、传输量及网络条件。窄窗口截图不能替代真实手机。

## 11. 验收与停止条件

### 小镇与操控

- 能完整走完上述短循环，所有交互都产生真实状态或可解释反馈。
- 新人能找到人物、门、案件本与下一步行动；工程候选先做脚本和 agent 检查，真人理解度单独保留。
- 玩家时间线、地图和词条不暴露未发现案件真相。
- 一轮持续操作后无未处理错误、存档损坏、重复动作或角色卡死；性能达到选定档位。

### 小说与共同真相

- 所有决定性线索在揭晓前已有明确段落；人物知道信息的顺序与来源一致。
- 同一案件的世界版本、可玩证据、章节线索和结局能互相定位。
- 通过故意篡改样本检查：换凶手、改时刻、删除关键线索、提前透露秘密时，应产生可定位的错误或待复核项。
- 断网、中断和续写可恢复；mock 与真实生成明确区分；导出不混入作者私密批注。
- 自动规则通过不等于小说好看。节奏、人物、语言和推理满足感仍需要后续独立阅读。

### 避免再次偏航

若还没有可读的街区、可控制角色与完整调查循环，不继续提升家具微细节。若核心事实校验失败，不继续批量续章。若性能超过预算，先减少同时可见内容和材质成本，不通过减少记录或更换统计口径宣称通过。

只在风格、时代、核心玩法或权利/付费范围这类关键选择上询问用户。日常建模和修复按已授权范围继续完成；完整候选达到工程门槛后，再引入独立艺术评审与读者/玩家测试。
