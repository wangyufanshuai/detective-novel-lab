# v9.7 Recovery Runbook

This runbook covers local Release Candidate validation and player-safe startup recovery. It does not authorize deployment, protected artifact regeneration, or deletion of user databases.

## Gate failure

1. Read the final `quality:rc` JSON `failures` array. The first failed stage includes exit code, timeout state, and stdout/stderr tails.
2. Reproduce that stage directly with the command shown by its package script.
3. Inspect the real response, DOM state, focus owner, runtime projection, or test invariant. Do not add blind retries or longer sleeps to hide a business failure.
4. Apply the smallest release-blocking fix that preserves frozen authority.
5. Run the failed stage, its adjacent contract tests, and finally the complete `quality:rc` gate.

## Isolated Server QA did not stop

The lifecycle helper normally terminates the spawned process tree and removes its unique database in `finally`. Diagnose before removing anything:

```powershell
Get-Process node -ErrorAction SilentlyContinue
Get-ChildItem .\data -Force | Where-Object { $_.Name -match '^(rc-|campaign-study-runtime)' }
```

Only terminate the process started by the current QA and only remove the matching RC-prefixed database plus its `-wal`, `-shm`, or `-journal` companions. Never delete the default development database or a path outside this repository's `data` directory. Then rerun the individual stage; repeated leakage is a release blocker.

## Corrupt or stale Continue state

- A malformed browser pointer is rejected and cleared locally; the Front Door offers a clean Campaign path.
- A well-formed pointer to a missing world/session is not treated as success. Continue remains open with retry/clean-start guidance.
- Reset/Create Town creates a new world only after explicit player action. Failed launch or extraction must not close the Front Door or persist a successful Continue pointer.
- Do not edit SQLite manually to manufacture a recoverable state.

## Network or request failure

- Keep the last confirmed client/runtime state.
- Confirm the UI presents localized public-safe recovery copy rather than a raw exception, internal identifier, path, or database detail.
- Repeating Join, launch, extraction, or world choice must remain idempotent or fail safely; duplicate clicks must not dispatch duplicate authoritative writes.

## Protected public hash changed

Stop the gate immediately. Do not run a catalog builder or artifact refresh to make the diff disappear.

```powershell
git diff -- public/dataset-reader
git diff -- public/review-catalog
```

Identify the exact command that wrote the file and compare it with the manifest's before/after tree hashes. Restore or regenerate protected artifacts only in a separately authorized artifact-release task. The v9.7 freeze commit must contain no protected-public changes.

## Local rollback

If the v9.7 freeze commit itself must be undone, prefer a normal `git revert` so the release history remains auditable. Do not use destructive reset operations in a dirty worktree. Preserve `.env.local`, local databases, Study exports, and untracked handoff notes outside any release commit.
