# v11.3 顶级世界模拟引擎与前端路线图

## 2026-10-07 产品方向修正

用户认为当前档案室不符合侦探小镇的整体目标，已确认采用 **Blender 3D 建模＋《星露谷物语》式角色探索和快捷工具栏**，并保留用于掌握人物与案件的全镇俯瞰。旧“逻辑之王推理工坊”与小镇在同一 Git 仓库的不同工作区；应复用世界/小说核心，恢复独立写作入口与正文生产流程。

执行方向以 [小镇与小说联合规划](vision/2026-10-07-town-and-novel/README.zh-CN.md) 为最新依据。四套地域美术概念尚未选定；v11 房间作为历史候选保留，v12 为未验收草稿。新制作顺序仍为后台 Blender 构图灯光 → 多视角渲染 → Function → Form → 浏览器和目标设备，但评审对象改为街区与角色探索。不得自动继续增加档案柜微细节来替代新方向。

这份路线图把“顶级”拆成可以复现、可以审计、可以回滚的工程门槛。它不把一次漂亮截图、一次长跑或一个 LLM 生成结果当成完成证明。每个阶段都要同时留下代码、运行收据和明确的未通过项。

## 目标架构

```text
权威输入/时间
    -> 固定 tick 世界核心
    -> 规范事件日志 + 来源链 + 状态摘要
    -> Agent 决策/记忆/关系与可审计工具命令
    -> CaseCandidate / playable case / investigation route
    -> room projection（玩家安全 / review 可追溯）
    -> React UI / 3D room runtime
```

边界规则：

1. **世界核心拥有真值。** Agent、LLM、React 和 3D 场景只能读取或提交经过验证的命令；它们不能直接写入死亡、案件真相或来源链。
2. **渲染与模拟分离。** 3D 房间接收稳定 projection，不能从临时 UI 状态推断案件；这与 [Lagless](https://github.com/GbGr/lagless) 的 no-view-coupling 方向一致，但本项目保留现有 JSON/SQLite 权威存储，不直接引入其二进制 ECS。
3. **回放以输入和来源为锚。** 同一种输入、同一 seed、同一版本的 canonical state 必须得到相同 digest；checkpoint、event log 和 outcome anchor 必须可以独立验证。
4. **公开与审计分面分开。** 玩家只拿到可探索信息；管理员和研究收据才可以看到 sourceEventIds、population ledger、decision traces 等内部字段。
5. **外部数据是候选输入。** 任何真实资料、开放世界包或第三方资产都必须带 manifest、许可证、hash 和 provenance，不能把搜索结果直接当成世界事实。

### 阶段 A：人口流动从显式适配器进入受控长跑

**状态：适配器、默认关闭的受控 cadence、真实 WorldPackage campaign 收据、newcomer 首次行动的持久 ledger 门，以及 12 包/2 seed/5,000 tick 的工程长跑候选门已完成；公平性人工审阅、生产性能门和人工理解度仍待补齐。**

后续门继续按 `population-flow-v1` 受控策略执行，默认关闭，并在独立 run profile 中审计：

- 只在来源链满足 arrival/replacement 条件时创建 newcomer；不能按 tick 或排名盲目轮换。
- 每次创建写入 `PopulationFlowRecord`、arrival `WorldEvent`、memory 和 agent 初始状态。
- 记录 `arrivalRate`、存活人口、关系边数、首次行动延迟、来源链完整率、重复 newcomer 数和 save/load replay hash。
- 先跑 100 tick 校验局部语义，再跑 1,000 tick 校验增长，再跑 5,000 tick 与无人口流动基线做成对比较。
- 通过条件：同 seed 重放 digest 相同；重复提交不增加人口；人口增长受上限约束；每名 newcomer 的来源、日程、关系和第一条行动都可追溯；案件重复率、证据完整率和运行时开销不回归。

为回归一次真实种子敏感性，`multi-package-seed-b` 收据覆盖同一 12 个包。此前 `power-station-blackout-town` 的启用轨道会因风险链选择到弱来源证据而丢失一个有效候选；现在风险链在每个阶段内优先可审计的强来源，并在长动作/Agent 事件写入证据后刷新同 tick 索引，同时从保留事件日志恢复被短期触发列表裁掉的案件触发。当前收据为 12/12 结构通过、12/12 deterministic repeat、质量回归 0、首次行动窗口违规 0，开启轨道共有 72 名 newcomer、180 个触发案件、13 个有效候选和 13 个证据覆盖；city-hall、hospital、wireless 三个无源包被明确列入 zero-flow。`test:population-flow-multi-package-seed-receipts` 固化了该包的候选数与证据覆盖不下降门槛。收据仍是 candidate，不代表跨更多种子、5,000 tick 或人工公平性已关闭。

### 阶段 B：规范回放包与分支

**状态：canonical digest、兼容性收据、回放包验证、隔离 checkpoint/命令执行和 WorldPackage receipt 已完成；更多命令类型与生产长跑证据仍待完成。**

`packages/engine/src/town/replay-contract.ts` 已提供一个不依赖墙上时钟的 `world-replay.v1`：

- 输入：world seed、规则包 hash、world package hash、命令序列、tick 间隔和明确的随机源版本。
- 状态：规范排序后的 NPC、关系、记忆、案件触发和 population ledger；排除 `createdAt/updatedAt` 等展示元数据，或将其标成非模拟字段。
- 收据：起始 digest、每个 checkpoint digest、结束 digest、事件数量、来源链数量、失败原因和代码版本。
- 能力：从 checkpoint 恢复、对两个 run 做 first-divergence diff、按命令分支、在执行前核对 engine/random source/tick interval 与 ScenarioPack/MapPack/RuleCatalog/WorldPackage/Experiment 兼容性，并拒绝缺失来源或未知规则包。

当前已验证：`buildWorldReplayDigest` 对同 seed 的不同 world/runtime id、`createdAt/updatedAt` 和 JSON 保存恢复保持一致；`world-replay-compat.v1` 会绑定 `persistent-town.v1`、持久化城镇 LCG、tick 间隔、当前实验的包/规则身份和 `world-package-receipt.v1` 收据 hash；`compareCanonicalReplayStates` 能返回稳定路径（例如 `$.world.name`）和变更值；带 world/events 的 run replay bundle 会携带 `replayDigest`。WorldPackage selection 现在同时持久化规范化包 hash、逐文件 SHA-256、字节数、许可、绑定 ID、验证结果和 receipt hash；缺少 content hash 仍 fail closed。持久化 checkpoint 现在额外保存 `replayDigest`，但隐藏的 checkpoint world/runtime 仍留在服务端；`verifyReplayBundle` 已接入回放包查询，逐项比对 digest、兼容性、checkpoint receipt、manifest runId 和命令 envelope，并明确返回 `verified`、`mismatch` 或 `evidence-insufficient`。`executeReplayFromCheckpoint` 会在副本中恢复 checkpoint，在执行前核对 checkpoint 与 live world 的兼容性，按 branch-scoped persisted commands 执行 scenario interventions，输出 digest，不写回 live world；管理员 Agent API `/api/v1/command/town/replay/execute` 已接入这条路径。旧包、缺少 checkpoint、兼容性漂移或查询时临时计算的 digest 不会被当成持久化证据。下一道门是用真实 campaign 输入重跑并比对 package receipt，同时补齐完整资产 manifest/provenance。

这里借鉴 [Flowstate](https://github.com/project-flowstate/flowstate) 的 fixed-step、state digest、initial/outcome anchor 结构；它的网络层和 Rust 实现不是本项目的依赖。

### 阶段 C：世界 Agent 工具链

**状态：`agent-control.v1` 能力发现、source-backed proposal、CAS/幂等 intervention、population-flow commit、case-extract、只读 reviewer、benchmark 与 package-export 专用执行器已完成；完整资产 manifest/provenance 与跨设备/长期验证仍待完成。**

当前 `agent-control.v1` 已通过 `/api/v1/query/town/agent-capabilities?worldId=...` 暴露版本化 command catalog；`POST /api/v1/command/town/agent/propose` 会在不改变世界的情况下解析 `world/brief/event/candidate/case/agent/observation/memory/intervention` 引用并返回可提交 proposal；`POST /api/v1/command/town/agent/commit` 使用同一解析器实现带 `actionId`、`expectedRevision`、`reason`、`sourceRefs` 的一次性提交。Agent API smoke 先选择带内容 hash 的 `dock-court-market-town` WorldPackage，再验证 compatibility receipt 复用同一 hash。重复 action 会返回原 intervention，不会重复写入，旧 revision 会返回 409。仍需补齐：

- `observe`：已由 runtime/brief/agents/agent capability 查询提供只读 public-safe projection、可用目标和当前 revision；agent/trace 查询会移除 private goal、known facts、resources、social profile、memory 与 source event ids。
- `propose`：已实现 source-backed、read-only 验证；现在会写入可跨进程复用的 `agent-proposal-receipt.v1`，由 `proposalId`/`receiptHash` 标识，重复提案复用同一收据且不推进世界 revision；管理员可通过 proposal query 恢复该收据。
- `commit`：当前已在 CAS 成功后写入带 actionId/reason/sourceRefs 的 intervention receipt；commit 可选地校验 `proposalId` 与提交载荷完全一致。每个 intervention 现在有 pending/applied/expired 状态，消费它的 decision trace 带回 actionId/reason/sourceRefs，并用 digest 绑定 intervention 与 trace；当 trace retention 裁掉完整 trace 时，runtime 会保留确定性的 intervention-linked archive receipt，管理员 runtime 返回 `agent-decision-trace-links.v1` 并区分完整、归档和断链记录。`commit.population-flow` 也已接入同一 CAS/sourceRef 边界，把 Agent action identity 和解析后的来源写入 `PopulationFlowRecord`，重复 action 返回原 arrival/event，旧 revision 与 source tuple 冲突均 fail closed。`commit.case-extract` 现在要求候选与触发事件的来源引用，沿用真实 `extractCase`/route-integrity 路径，并把 action、来源、候选和 case 绑定到持久 `agent-case-extraction-receipt.v1`；重复 action 重放同一 case/playable intake。`review.case` 是只读 CAS/sourceRef reviewer，重新计算 playable intake 与 review-mode 3D room projection，验证 route/source traceability，并写入 hash-bound `agent-case-review-receipt.v1`。`benchmark.emergence` 是只读 benchmark executor，按世界 seed 生成 10/20 条确定性评估轨道，绑定当前 compatibility/source refs，并持久化 `agent-benchmark-receipt.v1`；重复 action 在运行时版本变化后仍可恢复原报告。`package.export` 也已成为独立只读执行器：它只允许导出当前选中的、已验证的 WorldPackage，要求 world/package source refs 和 CAS revision，并持久化带文件级报告的 `agent-package-export-receipt.v1`；重复 action 在运行时版本变化后恢复原报告。
- `replay`：给定 runId/checkpointId，重放命令并验证 digest；冲突、缺失来源、越权字段均 fail closed。
- `package`：WorldPackage selection 已生成 `world-package-receipt.v1`，把 package hash、逐文件 hash、许可、来源相对路径、绑定包 ID、验证结果和 replay receipt hash 一起持久化。`package.export` 现在要求当前 selected package、world/package source refs 和 CAS revision，调用现有审计导出器并写入 `agent-package-export-receipt.v1`；重复 action 恢复原导出报告。`world-asset-manifest.v1` 现在为声明可视资产的包提供相对路径、字节数、SHA-256、许可证、来源、状态、人工批准和运行时验证的正式 schema；`accepted` 状态会 fail closed 地要求两道后置门。现有 12 个配置型 WorldPackage 尚未声明真实 3D 资产，程序化房间仍是 candidate-only，不能把该 schema 或 package receipt 当成 Form/Runtime/Human 验收。

借鉴 [MicroWorld](https://github.com/D2I-CUHKSZ/MicroWorld) 的“图、输入、轨迹、记忆、报告一起留存”原则，但继续使用本项目的 source-backed case contract，禁止让 LLM 生成内容绕过世界事件。

### 阶段 D：黄金调查路径与顶级 UI

**状态：真实 WorldPackage 软件黄金路径和真实浏览器路径的 candidate 收据已通过；人工理解度和正式艺术/运行时验收仍未关闭。**

固定一条可重复的黄金路径：

```text
source event
  -> trigger kind
  -> candidate / case extraction
  -> proof/evidence graph
  -> room projection
  -> player-safe route
  -> solved review unlock
```

必须同时有：

- player、review、solved 三种 projection 的字段差异合同；
- 1440 px、390 px、键盘、减少动效和无 JavaScript 错误的浏览器收据；
- route-step 和 evidence-node 的来源链检查；
- 真实案件数据驱动的截图或录屏，而非静态占位文本；
- 设计系统 token、状态层级、空/错/加载状态和可读性指标。

当前已新增 `scripts/run-real-worldpackage-golden-path.mjs`：它读取文件级验证的 `dock-court-market-town`，在 100 tick 的 source-signaled 运行中选择有效候选，执行真实案件抽取，并将原始事件与抽取视图合并后检查 `sourceEventIds`、记忆和观察来源。收据 `outputs/worldpackage-golden-investigation-path-dock-court-market-town.json` 记录 166 个来源事件、473 条记忆来源、473 条观察来源、route certificate、review room traceability、player 侧来源遮罩和 deterministic repeat；自动推理闭环为 11 步、19/19 proof obligations、通过。早期观察可能因 500 条运行时 retention 被逐出，但收据要求它们仍能从持久记忆的 `sourceObservationId` 解析；这证明当前来源链可恢复，不代表已有无限观察归档。

该收据仍是 `local-world-package-campaign` / `candidate`，`humanGate=pending-human-comprehension-and-ui-review`。下一道 UI 门已经落为真实浏览器收据，之后才把人工理解度与艺术方向引入验收。

### 阶段 E：真实 3D 房间与运行时门

**状态：程序化候选、`world-asset-manifest.v1`、实际 GLB 文件级字节/SHA-256 审计和真实 WorldPackage 浏览器 candidate runtime 收据已通过；Function/Form/正式 Runtime/人工验收仍未关闭。**

按用户最新指令，执行顺序固定为：

1. 后台 Blender 正式构图与灯光，保留可编辑的 `.blend`。
2. 四角、低机位、天花斜视渲染，和同一份模型及灯光绑定。
3. Function：先自主检查入口、空间功能、调查动线和操作目标；人工签收后置。
4. Form：检查材质、比例、接触、支撑、近景细节和整体艺术一致性，问题回到建模修正。
5. 浏览器及目标设备性能验收：核对实际加载资产，测量帧时间、内存、点击、低动效及恢复；本机窄屏模拟与手机实机证据分开。

待人工签收不阻止用户已授权的本地制作与候选验证，但不能自行把人工字段置为通过。

早期 Blender MCP 无法连接到 addon，但已确认本机 `D:\blender.exe` 可直接运行。用户已授权先用后台 Blender 自主推进建模、灯光和工程预检，再引入人工艺术验收；因此 addon 不再是本地制作阻塞。v1 的真实 WorldPackage 浏览器收据仍只证明旧候选运行时，不能替代新 Blender 资产的实际加载与材质测试。外部付费资产继续使用独立预算与来源边界。

## 质量门与停止条件

| 门 | 通过证据 | 未通过时的动作 |
|---|---|---|
| 真值 | source event、trigger kind、case、memory、population ledger 全部可解析 | 停止 UI/LLM 扩展，先修来源链 |
| 回放 | 同 seed 同版本 digest 相同；checkpoint first-divergence 可定位 | 不运行昂贵长跑，不宣称确定性 |
| Agent | actionId/revision/CAS/decision trace 完整，retention archive 仍可追溯，越权字段 fail closed | 只保留管理员命令，暂停自动 Agent |
| 人口公平 | 100/1,000/5,000 tick 成对收据，增长、重复、关系、案件质量无回归 | 保持 population flow 显式手动，不接入默认节奏 |
| UI | 桌面/移动/键盘/减少动效无溢出、无错误、来源字段稳定 | 继续使用 procedural preview |
| 3D Function | 人确认房间功能和动线 | 不花费资产预算 |
| 3D Form | 许可证、hash、尺寸、材质和渲染证据齐全 | 不把第三方模型并入包 |
| 3D Runtime | 目标设备性能和交互收据通过 | 不发布真实 3D 房间 |
| Human | 理解度、调查公平性、艺术方向由人签收 | 保持 `humanGate=pending` |
