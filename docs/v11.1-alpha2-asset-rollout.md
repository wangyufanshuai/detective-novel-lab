# v11.1 Alpha.2 Asset Rollout Contract

## 目标

Alpha.2 逐 Campaign 补齐 cover、map、三章 chapter、双 route finale、portrait 与 evidence assets，并在真实音频存在后接通 theme、ambience、route stinger、finale stinger 和共享 SFX。资产只负责表现，不进入 case truth、candidate、Route Certificate 或 judgement。

唯一许可台账是 `public/noir-archive/ASSET-LICENSES.md`。`planned` 是声明，不是资产；只有磁盘上真实存在且通过格式、尺寸、体积、hash、来源与许可检查的文件才能切换为 `ready`。

## 视觉资产批次

每个 Campaign 固定 19 项：

| 类别 | 数量 | 规格 |
|---|---:|---|
| cover | 1 | 1536×1024 WebP，≤360 KB |
| map | 1 | 1536×1024 WebP，≤420 KB |
| chapter | 3 | 1536×1024 WebP，每项 ≤220 KB |
| finale | 2 | 1536×1024 WebP，每项 ≤240 KB |
| portrait | 6 | 768×960 WebP，每项 ≤90 KB |
| evidence | 6 | 960×768 WebP，每项 ≤80 KB |

推荐按 `cover → map → chapters → finales → portraits → evidence` 推进单个 Campaign。每个小批次必须同时完成：真实文件、presentation manifest 的 `ready`、SHA-256、license register 行、`test:noir-presentation`。不要先批量改 `ready` 再补文件。

资产不得带 baked title、内部 ID、真相、答案标注或不可验证水印。地图可以表达区域氛围和路线层级，但不得暗示 culprit 或认证证据顺序。

## 音频状态机

每条音轨需要真实的 Opus 与 MP3 fallback 两个文件，且合计不超过 manifest 的 `maxCombinedBytes`。两者未同时存在、未登记来源许可、未通过真实文件头/解码/体积检查，或未分别登记两个 SHA-256 时，状态必须保持 `planned`。两种格式的 content hash 都必须由磁盘文件计算，不能复用一个摘要或手工填写。

禁止用 Web Audio oscillator、空容器、静音片段、重命名文件或其他合成占位音冒充 `ready`。`planned` 文件在磁盘上必须不存在；当 `readyAudioTracks === 0` 时，Browser evidence 必须证明页面没有请求任何 `.opus` 或 `.mp3`。只有真实授权音频及其双格式 fallback 同时通过 license register 后，运行时才可创建或播放该 track。

音频 cue 只能跟随 Focus、Commit、Resolve、World Reaction、New Objective 或明确的 warning；不得用声音透露隐藏真相。Low Sensory 和系统 reduced-motion 不等于静音，但必须停止循环强调、降低突发密度，并让所有状态仍可通过文字理解。

## 文案与人工检查

每个完成批次都要复核：

- en-US / zh-CN 意义等价，行动名称与当前目标一致。
- 390 / 768 / 1440 不裁切主体、不遮挡 focus ring、不产生页面横向溢出。
- 键盘可以到达每个动作，Escape / 返回后的 focus ownership 明确。
- 动效在 Low Sensory 与 `prefers-reduced-motion` 下保持信息等价。
- 由非作者执行 90 秒理解度检查，并由 art-direction reviewer 单独签署。
